GitHub Actions re-enabled with Mini Shai-Hulud payload still active
============================================================

Two compromised GitHub Actions linked to the Mini Shai-Hulud supply-chain attack were inadvertently re-enabled by their maintainer, exposing thousands of downstream repositories to malicious code for over a week.

### Key Points
- Security researchers at Socket discovered that two GitHub Actions, actions-cool/issues-helper and actions-cool/maintain-one-comment, were re-enabled on September 16.
- The re-enabled actions still pointed to malicious payloads from a May 18 supply-chain attack, which targeted developer credentials and CI/CD secrets.
- Approximately 15,000 repositories depend on the affected actions, which were finally disabled again by GitHub on September 25.
- The original Mini Shai-Hulud campaign compromised 323 packages and 639 versions on the npm registry.
- Socket recommends that developers rotate potentially exposed secrets and pin dependencies to verified, clean commits to prevent future unauthorized code execution.

### Why it Matters
This incident highlights the significant risks associated with using mutable tags in software supply chains, as automated workflows can silently pull malicious updates without developer intervention. Organizations must implement stricter dependency management practices to ensure that compromised third-party tools do not provide attackers with persistent access to sensitive CI/CD environments.
